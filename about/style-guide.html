Style guide

Overview of the principles and specific steps we use to make our material professional and consistent

Published

29 September 2026

Last updated

6 October 2026

To ensure that all material on the site is consistent, the following principles are to be used by all authors and editors. This material is insipred (and is a succinct version) of other guides such as The Turing Way style guide.

Principles

NoteDraft

Draft principles being flushed out

  • Clarity

  • Consistency

  • Neutrality - we provide guidance on what could be done or what are seen as sensible defaults (if they are set in the discipline). Where there is disagreement in the discipline, the options are outlined.

  • Browsability - the content here is not meant to be very technical or hard to read and digest. Content is fundamentally designed to be an overview. Hence content is written so that readers can quickly browse through a set of pages, find a seciton that interests them, and read through it.

Specifics

For a good overview of all the options, check out the Authoring section in the Quarto docs, starting with markdown basics.

Metadata

Quarto uses the metadata specified in each .qmd file to format the page. For an overview, check out the formats that are supported, with specific focus on the html format. The default minimum metadata per page should be:

---
title: "Style guide"
subtitle: "Overview of the principles and specific steps we use to make our material professional and consistent"
date: 2026-09-29
date-modified: last-modified
draft: true
---

# Text of article
  • title - states the (short) name of the page
  • subtitle - a summary of the page. Optional
  • date - when the article was last published
  • date-modified - when the article was last updated. Note, for many pages, this is set at a hard coded date to start. However once you edit the page, please change this to a value of last-modified, which will make Quarto render it automatically to the date the specific .qmd file was changed.
  • draft - whether there is an orange draft header to the page or not. You can use this to publish draft pages for review (draft: true) before they are considered final (either set it as draft: false or remove the draft from the top of the yaml)

Page overview

Each page should start with a sentence or two at the top introducing the metarial, then headings per topic, and sub-headings (h2) for sub-parts

Writing and formatting text

Text follows common approach specified by markdown (for example heading, bold, italic, etc). Checkout the summary on markdown basics for a good walkthrough.

A few dos and donts:

  • Do - use headings widely.
    • Making it easy for readers to browse pages and parts of specific pages to zero in to the content they are looking for
  • Do - use lists, diagrams, callouts, and other formatting liberally
    • Again, the goal is to make it easy to read and understand content.
  • Don’t - write long technical paragraphs
    • Big and bulky paragraphs or too many paragraphs together make it hard for readers to zero in to the content that would help them most.
  • Don’t - use new line separation (or by pressing enter) for each sentence and two spaces per paragraph.
    • Quarto will merge together separate sentences and will format paragraphs appropriately. Separating things out allows us to track changes per sentence in git. See new line breaks guidance in the Turing Way style guide for a full explanation.

Tables

There are many ways to make tables. The minimum default is to separate the id of the table and to give it a title. That way you can reference the table in the text.

For example:

| fruit  | price  |
|:-------|--------|
| apple  | 2.05   |
| pear   | 1.37   |
| orange | 3.09   |

: Fruit prices {#tbl-fruits .striped .hover}

In the body of your text, you can reference the @tbl-fruits.

Will rendered as follows

In the body of your text, you can reference the Table 1.

TipOptions

There are several options you can use to configure how the table looks. For example incliding .sm within the parameters in the curly brackets makes the table text smaller to fit it better to the page width.

Formulas

Quarto renders LaTex equations, meaning basic LaTex formulas can be used. Using visual mode in vscode or Rstudio is the easiest way to write and display these at the same time.

Formulas are surrounded by a single $ for inline (i.e. within the text) or two of bulk formulas in the middle of a page.

For example:

$$
P_{J}^{0, t}=
    \prod_{i \in G_{0, t}} \left(
        \frac{p_{i}^{t}}
             {p_{i}^{0}}
        \right)^{\frac{1}{N_{0, t}}} 
$$

Is the Jevons index, where $G_{0,t}$ is a set of matched products in both months 0 and t.

Will display as

\[ P_{J}^{0, t}= \prod_{i \in G_{0, t}} \left( \frac{p_{i}^{t}} {p_{i}^{0}} \right)^{\frac{1}{N_{0, t}}} \]
