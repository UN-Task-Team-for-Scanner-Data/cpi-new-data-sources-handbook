How to evaluate classification methods

There are numerous metrics that can be tracked and applied when evaluating how well a classifier performs. This chapter provides an overview of common approaches using a Machine Learning (ML) classifier (i.e. Method 4 and in some cases Method 3) as the use case throughout due to their applicability and popularity with ML. These metrics however, could also be applied on classifiers created with other methods (such as Method 2) as long as there is a representative test dataset on which to evaluate classifier performance.

Approaches to evaluation

When supervised machine learning is used for classification, the data it is trained on is separated into three parts: training data on which the model is trained; validation data on which hyperparameters are selected; and a test set on which the model is evaluated. The test data set has never been seen by the model during training and parameterisation, so it is used for the final evaluation of the model. The idea is to evaluate the model on the same distribution the model was trained on but have that test dataset represent 'out-of-sample' performance, simulating how generalizable the learning has been. The risk of not doing this is that the model could be overfitted to its' training data. In the case of overfitting, the model would virtually learn the data by heart instead of recognizing the patterns behind it. There are different ways to select the test data, which typically includes a somewhat more complex procedure for splitting the data set multiple times and training the models, which is called cross-validation. In cross-validation the data is split into k parts, one part of the data is used as a test data set and the other k-1 parts for training the model, this division is repeated several times. In this way, different models can be compared.

Since the method is supervised, the test dataset contains the actual (intended) classes and the predicted classes by the model being tested. There are numerous metrics that are used to evaluate machine learning models by comparing these predicted and actual categories. These are usually built on a confusion matrix, which provides an overview of which items have been correctly or incorrectly classified.

Binary classification

For simplicity, we start with a binary case with two classes.

Table 1: A two by two confusion matrix


 Predicted positive Predicted negative
Actual positive True Positive (TP) False Negative (FN)
Actual negative False Positive (FP) True Negative (TN)

Several metrics can be calculated from this:

  • Accuracy is the proportion of correct predictions out of all predictions made. Accuracy is also an indicator of the overall classification task (i.e. summarizes the situation for both positive and negative classes as one metric).

\(\text{Accuracy} = \frac{\text{correct predictions}}{\text{all predictions}}= \frac{tp + tn}{tp+tn+fp+fn}\)

  • Precision is the proportion of correct predictions out of all predictions estimated as positive. It is calculated individually for each class.

\(\text{Precision} = \frac{tp}{tp+fp}\)

  • Recall (also called sensitivity) is the proportion of true positives out of all positive observations. Similar to precision, it is calculated for each class.

\(\text{Recall} = \frac{tp}{tp+fn}\)

Ideally, we want a high precision and a high recall. Precision and recall do not necessarily both increase, they can also behave in opposite ways. Both can be combined through an F1 score:

  • F1 score is the harmonic mean of precision and recall. The F1 score shows how precise the model is, as well as how robust it is. If one of the two metrics is much lower than the other, then the F1 score is lower than the arithmetic mean of the two scores.

\(\text{F1} = \frac{2tp}{ (2tp+fp+fn)} = 2\frac{\text{precision}* \text{recall}}{\text{precision} + \text{recall}}\)

Accuracy and F1 score are very commonly used scores to evaluate a classifier. Accuracy is very easy to interpret, but it also has weaknesses especially with heterogeneous distributed class sizes (or imbalanced data). Suppose you have one class with 99 observations and a second class with one observation. If the classifier always estimates the first class, it will have an accuracy of 99%, however it will always miss the second class, which is undesirable. 

Example 1: Suppose we have 10 items to be classified, 2 milk and 8 yogurts. If the classifier classifies one milk item correctly and the other milk as a yogurt and all yogurts correctly, we get the following scores. 

  • Accuracy = 9 / 10 = 0.9 or 90% correct
  • F1 for Milk = (2*1)/(2*1+ 0 + 1)= 2/3 = 0,5 = 66,7%
  • F1 for Yoghurt = (2*8)/(2*8+1+0) = 16/17 = 94.1%

In this example with unequal class distribution, accuracy is less suitable. F1 metrics also tell different stories depending on the class you calculate them for. 

Multi-dimensional case

Let us now consider the multidimensional case, as most applications will typically involve a classifier predicting to one of multiple classes, not simply 2. We have n classes: C1, C2, ..., Cn. \(N_{i,j}\) is the number of observations belonging to class Ci and classified in class Cj (Table 2). For each individual class Ci, the metrics introduced above can now be calculated by creating a one-vs-rest matrix, i.e. all observations that do not belong to class Ci are summed up (Table 3).

\(\text{precision}_i = \frac{tp}{tp+fp}= \frac{N_{i,i}}{N_{i,i}+\sum_{j \ne i}{N_{j,i}}}]\)

\(\text{recall}_i = \frac{tp}{tp+fn}= \frac{N_{i,i}}{N_{i,i}+\sum_{j \ne i}{N_{i,j}}}\)

\(\text{F1}_i = 2\frac{\text{precision}_i* \text{recall}_i}{\text{precision}_i + \text{recall}_i}\)

To consider the performance of a model as a whole for all classes, instead of individually on a class-by-class basis, two ways to calcuate are common - micro scores or macro scores. For the micro scores, the true positives, true negatives, false positives and false negatives of all classes are added together and then the scores are calculated according to the above formula. The macro scores are calculated from the arithmetic mean of the scores of the individual classes.

\(\text{macro precision} = \frac{1}{n} \sum_{i=1}^n{\text{precision}_i}\)

\(\text{macro recall} = \frac{1}{n} \sum_{i=1}^n{\text{recall}_i}\)

\(\text{macro F1} = \frac{1}{n} \sum_{i=1}^n{\text{f1}_i}\)

The macro F1 score considers large and small classes equally. As a result, observations from a large class have less influence on the score than observations from a small class. This effect is stronger the larger the imbalance in class sizes. It is relatively easy to recognize when any class has very poor scores. Whether this differential influence is desirable or not must be considered from a specialized point of view. An alternative would be to assign weights to each class and calculate a weighted average. Possible weights would be class size or, in the context of price statistics, turnover and weighing.

"Advanced methods"

F-beta

A more generalized version of the F1 score defined above is the F-beta score:

\(\text{f}_\beta = (1+ \beta^2)* \left( \frac{\text{precision}* \text{recall}}{\beta^2 * \text{precision} + \text{recall}}  \right)\)

Depending on the value for beta, precision or recall has a stronger influence on f-beta. A value smaller than one means, that there is more weight on precision. A value bigger than one means more weight on recall. 

In the multidimensional case, there is another component that plays a role. We defined the F1 macro above, in which the individual F1 scores are determined using a simple average. An alternative here is to use a weighted average. In the case of our classification according to COICOP, for example, it makes sense to use the COICOP weighting scheme as the weight. In this way, more influential COICOPs are weighted higher, regardless of the class size. Precision has been seen as more important for the price statistics applications as it helps mitigate misclassification bias in the price index calculated after classification by making sure there are less false positives in the category (3, 5). 

ROC curve

Another option NSOs cold leverage is the ROC curve. An ROC curve can be seen as a visual representation of the tradeoff between the costs of true positive and false positive (4). The isolines each represent different parameter combinations with the same accuracy. If the ROC curve is close to the diagonal, this indicates that the classifier is not better than one random guess. A classifier’s ROC curve is optimal when it rises sharply along the true positive axis before increasing along the false positive axis. As ROC curves can be swept out by manipulating the balance of training samples for each class, NSOs can apply sampling strategies to try to select a desired classifier. ROC curves can be leveraged by NSOs on a multiclass use case by applying one vs one or one vs rest evaluation approach.
